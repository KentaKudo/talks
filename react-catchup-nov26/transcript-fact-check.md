## React

- **Confirmed:** React 19.3 was released September 9, 2026, stabilising View Transitions and Fragment refs. It also added Trusted Types integration and direct rendering of client-defined context providers in Server Components. Clarified that Trusted Types still requires policies/CSP; the context change does not enable server-side context creation or consumption. [Release announcement](https://react.dev/blog/2026/09/09/react-19-3), [Server Component context guidance](https://react.dev/reference/rsc/server-components#rendering-a-context-provider-in-a-server-component).
- **Confirmed:** Experimental View Transitions were documented April 23, 2025. `startTransition`, Suspense reveals, and deferred updates can trigger animations; urgent updates do not. CSS classes and animation callbacks customise them. [React Labs announcement](https://react.dev/blog/2025/04/23/react-labs-view-transitions-activity-and-more).
- **Confirmed with scope:** Chrome shipped same-document transitions in 2023 and cross-document transitions in 2024. Current same-document support includes Chrome/Edge 111, Safari 18, and Firefox 144. Cross-document support includes Chrome/Edge 126 and Safari 18.2; Firefox is listed as preview, rather than stable. Individual transition features have separate support requirements. [Chrome history](https://developer.chrome.com/blog/view-transitions-in-2025), [same-document compatibility data](https://github.com/mdn/browser-compat-data/blob/main/api/Document.json), [cross-document compatibility data](https://github.com/mdn/browser-compat-data/blob/main/css/at-rules/view-transition.json).
- **Confirmed:** Explicit `<Fragment ref={...}>` supplies a `FragmentInstance`. Focus methods search nested children; `observeUsing` registers first-level DOM children with an IntersectionObserver or ResizeObserver. It does not turn the Fragment into a DOM node or observe one combined bounding box. [Fragment reference](https://react.dev/reference/react/Fragment).
- **Clarified:** `browser` comes from `react-dom`; marking a component browser-only requires `use(browser())` in a Client Component with a surrounding Suspense boundary. Calling `browser()` alone does nothing. [API reference](https://react.dev/reference/react-dom/browser).

## Next.js

- **Confirmed:** Next.js 16.4 was released October 6, 2026. Its recommendation for Cache Components, `create-next-app` defaults, planned Next.js 17 default, and agent upgrade support match the announcement. `agentUpgrade` and `agentFeedback` are experimental options. [Release announcement](https://nextjs.org/blog/next-16-4).
- **Confirmed:** The caching-history summary is supported by Next.js 15’s changes to fetch, GET handlers, and client navigation defaults. [Next.js 15 announcement](https://nextjs.org/blog/next-15).
- **Confirmed:** `cacheLife` and `cacheTag` control lifetime and targeted revalidation. [Cache Components guide](https://nextjs.org/docs/app/getting-started/cache-components).
- **Confirmed with prerequisite:** `ensureStatic = 'navigation'` requires Cache Components and enforces static server-rendered route output. Pages and layouts can export it; request-time work that violates it causes build failure. [API reference](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic).
- **Corrected:** `await navigation()` excludes subsequent runtime work from the app shell and per-link prefetches with Partial Prefetching. Static prerenders can still include that content, so saying it excludes all prefetching was too broad. [API reference](https://nextjs.org/docs/app/api-reference/functions/navigation).

## TanStack

- **Confirmed / unresolved detail removed:** Start’s stable 1.0 milestone was announced October 13, 2026. The announcement describes early work in December 2023 and the Start package rename in May 2024; it does not establish a June 2024 first announcement. That specific month was not independently substantiated and has been removed, not declared false. [Stable announcement](https://tanstack.com/blog/tanstack-start-1-0).
- **Confirmed with qualification:** Redact was announced October 26, 2026 as a smaller browser runtime. It renders synchronously without time slicing or interruptible rendering. React API compatibility does not guarantee identical behaviour: transition hooks remain available, while native View Transition animations are experimental and opt-in. The Preact comparison is an analogy, not a claim of identical compatibility. [Announcement](https://tanstack.com/blog/introducing-tanstack-redact), [compatibility documentation](https://tanstack.com/redact/latest/docs/compatibility).

## React Compiler

- **Confirmed:** Compiler 1.0 shipped October 7, 2025. Reworded the assertion about the team’s overall priorities as the speaker’s choice to focus on tooling. [1.0 announcement](https://react.dev/blog/2025/10/07/react-compiler-1).
- **Confirmed / clarified attribution:** The original TypeScript implementation ships as a Babel plugin. The React team ported the compiler to Rust; Oxc adapted it to operate on its own AST. The toolchains did not independently invent unrelated compilers. [Upstream TypeScript source](https://github.com/react/react/blob/main/compiler/packages/babel-plugin-react-compiler/src/Babel/RunReactCompilerBabelPlugin.ts), [Oxc integration history](https://oxc.rs/blog/2026-08-18-react-compiler-support).
- **Confirmed with qualification:** Oxc announced support in August 2026. Vite 8 integration is opt-in through `@vitejs/plugin-react` 6.1+ and `oxc-transform-react`, and remains experimental. [Oxc announcement](https://oxc.rs/blog/2026-08-18-react-compiler-support#vite), [plugin README](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react/README.md#rust-react-compiler).
- **Confirmed with benchmark scope:** The published two-fixture measurements are 12.31× and 15.37× versus Babel on an Apple M3 Max. These are synchronous compiler transforms excluding source maps and JSX lowering, not end-to-end app builds or browser runtime speedups. [Published benchmark](https://github.com/oxc-project/bench-transformer#react-compiler).
- **Confirmed:** The standard Next.js integration runs Babel with an SWC file filter. Next.js 16.3 introduced an experimental Rust path inside Turbopack. [Standard integration](https://nextjs.org/docs/app/api-reference/config/next-config-js/reactCompiler), [16.3 announcement](https://nextjs.org/blog/next-16-3#rust-based-react-compiler).

## Completion pass — 2026-11-24

- **Start application model:** Type-safe routing, explicit server functions, SSR, and continuity with client-side application patterns match the [stable announcement](https://tanstack.com/blog/tanstack-start-1-0). Server functions run server-only handlers and serialize calls across the boundary; loaders are a supported caller. See the [server functions guide](https://tanstack.com/start/latest/docs/framework/react/guide/server-functions). The deck-specific walkthrough was checked against `src/deck/get-slides.ts`, `src/routes/index.tsx`, and the existing static-build documentation. Navigation uses the hydrated deck data; it does not load a slide on every click.
- **Experimental RSC:** Start's Server Components integration is explicitly experimental and opt-in. Its documented `renderServerComponent` helper returns a renderable value through a server function and loader. The transcript describes the existing illustrative slide, not an enabled feature of this deck. Moving a Markdown parser or highlighter to the server is a hypothetical use case, not a measured bundle saving. [Server Components guide](https://tanstack.com/start/latest/docs/framework/react/guide/server-components).
- **Redact scheduling:** Synchronous rendering, retention of previous results while work suspends, and experimental opt-in View Transition animations match the [compatibility guide](https://tanstack.com/redact/latest/docs/compatibility). Main-thread responsiveness is an engineering implication of synchronous rendering, not a performance measurement of this deck. The transcript's suitability discussion is the speaker's assessment.
- **Redact versus Preact:** The comparison is limited to TanStack's published, versioned framework fixtures. Both tested Start versions passed with Redact and failed with the standard Preact setup. This does not establish universal application compatibility or rule out custom Preact integrations. [Framework compatibility matrix](https://tanstack.com/redact/latest/docs/framework-comparison).
- **Local bundle evidence:** `src/deck/build-comparison.json` records React at 116,156 gzip bytes (113.4 KiB) and Redact at 69,102 gzip bytes (67.5 KiB), a 40.5% reduction after rounding. These count minified client JavaScript chunks, not all downloaded resources or the runtime alone. The shared native React demo bundle is excluded. Source and measurement scope were inspected; builds were not rerun for this documentation change.
- **Compiler recap and history:** Automatic build-time memoization and the requirement to follow the Rules of React match the [introduction](https://react.dev/learn/react-compiler/introduction). The 2021 prototype, 2024 open-source release, April 2025 RC, and October 2025 stable release are described in the [1.0 announcement](https://react.dev/blog/2025/10/07/react-compiler-1).
- **Local build timings:** The existing `compiler-build-time` slide records nine alternating runs per configuration on an Apple M2: Babel median 756 ms (721–887), Rust/Oxc 573 ms (548–811), compiler disabled 591 ms (554–939). The median reduction from Babel to Rust is 24.2%, rounded to 24%. Client and server production builds exclude prerendering and demo rebuilding. These are inherited slide measurements: no raw per-run log was found, and this pass did not rerun or independently reproduce them. The transcript explicitly avoids inferring that enabling the compiler speeds builds relative to disabling it.
- **Compiler output and verification:** The narration matches the stored emitted `SlideTitle` comparison in `src/deck/build-comparison.json`: compare the `title` input, cache the heading element, and reuse it when unchanged. This verifies a transformation, not a measured user-facing speedup. The existing DevTools screenshot is from the native React setup; the [installation guide](https://react.dev/learn/react-compiler/installation#verify-your-setup) documents the Memo badge.

This completion pass changes prose only. It does not change the deck, runtime, demos, or benchmark artifacts. Live demos and builds were not rerun. Rehearsal timing is an estimate from spoken word count; audience responses and demo pacing need an actual rehearsal.
